# Архитектура проекта tTerm и серверной экосистемы

## 1. Назначение системы
**tTerm** — платформа для удалённого управления серверами, рабочими станциями, терминальными сессиями и оркестрацией ИИ-агентов. Включает веб-интерфейс, агент для машин (Windows, macOS, Linux), Telegram-бот управления и встроенный MCP-сервер.

## 2. Ключевые компоненты
- **tTerm Server (FastAPI + Python 3.12)**:
  - Порт `8290`: веб-интерфейс и API для браузера/приложений.
  - Порт `8291`: защищённый входящий туннель для агентов машин.
  - База данных: PostgreSQL 16 (`tterm_web`).
  - Сертификация и CA: локальный Signer на базе эллиптических кривых/ED25519 для авторизации терминальных сессий.
- **Telegram Bot (@ttermnofbot)**:
  - Long polling loop, интеграция с ядром tTerm.
  - Двухуровневый доступ:
    - *Обычные пользователи*: базовые команды (`/start`, `/machines`, `/projects`, `/help`, `/support`, `/language`), регистрация/привязка Telegram, просмотр ТОЛЬКО своих машин.
    - *Владелец платформы*: Telegram ID `55570186` / `@eklimov` / `@eklimov84`. Доступ к панели администрирования (`/admin`), управлению пользователями (блокировки, тарифы, смена планов, отвязка устройств), общим метрикам системы.
  - UI-технология: **Telegram Rich Messages** с интерактивными блоками, эмбед-кнопками внутри пузыря сообщения и адаптивной сменой языка.
  - Скоупы меню: быстрые админ-команды через слэш регистрируются строго через `BotCommandScopeChat(chat_id=55570186)`, обычным пользователям видны только безопасные команды `BotCommandScopeDefault`.
- **Мультитенантная изоляция данных (Strict Multi-Tenancy)**:
  - `/api/orchestration/projects-list`: фильтрует строго по `owner_id = user.id OR pm.user_id = user.id`. Без авторизации возвращает пустой список `[]`.
  - `/api/orchestration/nodes`: выдаёт только машины, привязанные к проектам текущего пользователя.
  - `/api/orchestration/git-configs`: отдает только репозитории проектов пользователя (чужие возвращают 403 Forbidden).
  - `/api/orchestration/vault/*`: хранилище секретов строго привязано к `user.id`.
  - В боте: при отсутствии у пользователя своих машин отображается приветственная карточка с кнопкой «Добавить машину», чужие сервера никогда не подмешиваются.

## 3. Сетевая топология VPS (82.148.241.254)
- Внешний Nginx:
  - `https://tterm.e-klimov.ru` -> проксирует на `127.0.0.1:8290` (контейнер `tterm-server-tterm-1`).
  - `https://e-klimov.ru` -> статика сайта `/opt/infra/data/www/e-klimov.ru/html/`.
- FRP-сервер: порты `7000`, `8090`, `8124` для туннелирования внешних машин за NAT.

## 4. Тестирование и верификация
- Модульные тесты изоляции: `python3 -m unittest tterm/tests/test_tenant_isolation.py` (4 теста: projects, nodes, git-configs, vault).
- Тесты прав и админки бота: `python3 -m unittest tterm/tests/test_bot_admin.py` (4 теста: изоляция кнопок, прав владельца, защита callback-запросов, генерация Rich Messages).
- Запуск тестов в контейнере:
  ```bash
  docker exec -w /app tterm-server-tterm-1 python3 -m unittest tterm/tests/test_tenant_isolation.py tterm/tests/test_bot_admin.py
  ```
